## Decisions taken without the user (PLAN §1.17 rule)

- **D-P2-1 Actions are dry-run by default.** Flag `actionsLive`, built-in default `false`: every `rt.react.actions` call is logged, never run, until V1 sets `actionsLive: true` in `device/defaults.json` at release. Also in test mode whatever that flag says: P1's action-logger switch, `actions.test(true)`, an untrusted (synthetic) mouse or pointer event, or an unreadable test state. Reason: ~20 agents drive the live UI during the build; a launch must never happen by accident (never-list).
- **D-P2-2 Lazy scan.** `install()` only creates `rt.react`; the one source scan runs on the first call that needs it. With no T3 caller enabled nothing is scanned or patched.
- **D-P2-3 `actions` vs `nav`.** `actions.navigate` is for user-intent jumps (game pages, library tabs) and is logged in test mode; `nav.go` is plain navigation inside our own views and always runs.
- **D-P2-4 Bare function components are patched through Steam's element factories.** A component with no shared holder (PagedSettings, the status pill) would lose a fiber `type` patch on every remount. While such a patch exists, `jsx`, `jsxs` and `createElement` of Steam's own React substitute our trampoline for that one function (one `Map` lookup per element; RX-FN, RX-REMOVE). Safe default: the hook exists only while a bare-function patch does, removal restores the originals (checked by `patchedLeft`), and the cost is one possible remount of the live instance when a patch is added or removed.
- **D-P2-5 `rerender` uses only Steam's own update paths.** `forceUpdate()` for classes and mobx's own `stateVersion` + `onStoreChange()` for observers; nothing else is forced (no state is changed to provoke a render).
- **D-P2-6 The error page's title is English-only.** Steam has no token for "This view could not be shown"; per PLAN §1.15 the title is drawn only when the UI language starts with `en`, and the focused Back capsule (`#Button_Back`) is always there.
