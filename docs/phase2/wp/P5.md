## Decisions (PLAN §1.17 rule: safe default, noted here)

- **D-P5-1 Reduce Motion durations.** PLAN §1.5 and VP P-56 ask for fades of at most 200 ms. Every duration token
  is redefined under `prefers-reduced-motion: reduce`: 150 ms (`hover-in`, `interactive`, `morph-close`, CTL §4's
  "150 ms fade from .6"), 200 ms (`sheet-in`, MO §4.8), 180 ms for the rest (`--lgs-d-reduce`); `glow-off`,
  `swap`, `page-out` keep 90 / 120 / 150 ms. Bounce curves become b0 (D2 §16).
- **D-P5-2 Reduce Motion keyframes.** Instead of asking every caller for a media query, each `lgs-*` keyframe is
  redefined inside the media query as opacity only (content and decorative keyframes empty). Proven mechanism:
  P5-K2.
- **D-P5-3 Extra keyframes.** Context packages own no `*.nowrap.css` file, so every keyframe they need must be
  here. Added beyond the card's list, from the concepts: `lgs-mat-large-in` (alerts, R8), `lgs-sheet-content-*`,
  `lgs-morph-content`, `lgs-catch` (MO §4.6), `lgs-knob-lift` (MO §4.15, CTL), `lgs-shift-in` (SET §SteamVR
  switch), `lgs-fade-in/-out`, `lgs-edge-in` (GP scroll edge). The card's `lgs-morph` is the clip keyframe of
  MO §6.4.
- **D-P5-4 Extra fixed tokens.** `--lgs-d-page-out` 150, `--lgs-d-glow-off` 90, `--lgs-d-swap` 120,
  `--lgs-d-reduce` 180 and the delay tokens (`--lgs-delay-*`, `--lgs-stagger`) carry durations the specs name
  outside D2 §11.2's table, so call sites never write literals (P-58).
- **D-P5-5 Not defined here.** `--lgs-press-grow`, `--lgs-press-max`, `--lgs-focus-first`, `--lgs-card-lift`,
  `--lgs-disc-lift` are P4's (contracts/tokens.md); `lgs-focus-in` reads `--lgs-focus-first`.
- **D-P5-6 No `@property` in 02-motion.** The card lists "@property declarations", but P4 already registers
  `--lgs-hover`, `--lgs-press`, `--lgs-focus` (identical to D2 §16) with the states that use them. A second
  registration in the later 02 file would silently override any future P4 change, so P5 registers none; no
  keyframe needs one.
- **D-P5-7 Exit curves sit at the hold offset.** The first live MO-3 run (session 1, 04:28) showed that Chromium 126
  merges the implicit start values of the other properties into an explicit `0%` keyframe, easing included, so a
  custom coverage curve on `0% { opacity: 1 }` also drove `scale` and `backdrop-filter`. `springs.py`'s `tail_of()`
  now finds where the exit curve leaves 1 (86.5 % for `lgs-mat-glass-out`, 26.5 % for `lgs-sheet-out`) and puts the
  curve on a keyframe at that offset; `0%` keeps the caller's easing. Version `ff9644ee1e` → `2428c76f74`. Proven by
  MO-3's samples: `lgs-mat-glass-out` scale stays 1 until 55 % and is 1.0167 at 75 % (the `--lgs-ease-mat-out` curve).
- **D-P5-8 Large glass fades over the glass channel.** First version: every keyframe used glassd's coverage alpha
  `smoothstep(0, .3, m)` (MO §9). The live filmstrip next to `window-nav-motion.html` showed alerts and sheets popping
  in (fully opaque by 69 ms and 110 ms) where the storyboard fades them over most of the glass channel. In glassd the
  frost, tint and lensing keep ramping until m = .92, so the slab still materializes; a large CSS slab may not ramp
  its blur (MO R8), so its opacity is the only glass channel left. P5 now gives large glass the perceived optics ramp
  instead: `min(1, m / .8)` (`LARGE_COVER` in `springs.py`; light 0–.6 with frost and tint .2–.92 average to about
  that), and the mirror on exit, `min(1, (1 − p) / .8)`. The storyboard draws 1.3 g (alert), 1.25 p (sheet in) and
  1 − ramp(p, .25, 1) (sheet out); measured live: alert .20 / .48 / .68 / 1 at f .15 / .35 / .5 / .75 of 250 ms,
  sheet in .50 at 110 ms (storyboard .50), sheet out .75 / .21 / .07 (storyboard .80 / .22 / .08). Small glass and
  toasts keep glassd's coverage, because their blur, tint and shade ramp alongside. glassd itself is unchanged.
- **D-P5-9 Menu morph clip has no overshoot.** The storyboard's morph row shows the b .20 `morph-open` overshoot
  (1 %); `lgs-morph` clips on the b0 curve as MO §6.4 specifies (a negative `inset()` is not dependable); glassd draws
  the overshoot in native mode. Measured: clip 40 % at 91 ms (storyboard 41 %), 83 % at 212 ms (90 %).
